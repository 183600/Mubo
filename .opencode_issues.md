# Bug Report: `--no-static=false` and `--no-ws=false` CLI flags don't re-enable features

## Location
File: `src/core/config.ts`
Lines: 347-369

## Problem
When passing `--no-static=false` or `--no-ws=false` to explicitly re-enable static serving or WebSocket, the value remains disabled if it was previously set to off.

## Expected Behavior
- `--no-static` → static.mode = "off"
- `--no-static=true` → static.mode = "off"
- `--no-static=false` → static.mode = "disk" (enabled)
- Similar for `--no-ws`

## Root Cause
In the `argvOverrides` function, when `enabled === false`:
```ts
if (enabled) result.static = { ...result.static, mode: "off" };
```
This does nothing when `enabled` is `false`, so if the mode was already "off", it stays "off".

## Fix
Change to:
```ts
if (enabled !== undefined) result.static = { ...result.static, mode: enabled ? "off" : "disk" };
```

Same pattern for `--no-ws`:
```ts
if (enabled !== undefined) result.ws = { ...result.ws, enabled };
```
